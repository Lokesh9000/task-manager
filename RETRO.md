A rule a PreToolUse hook cannot enforce is "do not introduce new Ruff findings, and keep the tests green after every change". A PreToolUse hook sees one proposed call before it runs, has no memory of earlier calls, and cannot see the code as it will be afterwards. Whether a change adds a lint finding or breaks a test is only known once the edit exists. The logs show the cost of leaving it to prose: `audit-errors` asks for `pytest -q` after each changed function, and in run `5be49367` Claude ran it once after its single edit, and nothing would have stopped it from skipping that run. `verify-scope` run `7ad897ca` showed that even the after-the-fact comparison is subtle: it needed a baseline by file and rule code, and my first version of that rule gave a false OUT OF SCOPE. The right tool is a PostToolUse hook, or a Stop hook, that runs `pytest -q` and `ruff check .`, compares the findings with the five baseline ones, and fails the turn on a regression, with the same check in CI. I have not built that. `verify-scope` is the manual version of it for now.
